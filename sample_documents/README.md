# Recommended AI Project demonstration dataset

Upload the six files in this folder together into a new workspace. Do not upload this README. The documents all describe **AI Project Intelligence & Risk Advisor**, project **AIPI-DEMO-26**, at **2026-10-07**.

This is a fictional demo scenario, not an amendment to approved M1-M4 history, a claim of actual defects, or a record of real people being assigned work. All dates, owners, task states and risk assessments are explicitly stated sample evidence.

## Files

- AI_Project_Proposal.pdf — scope, architecture, deliverables, responsibilities and milestones.
- AI_Project_SRS.docx — requirements, user stories and evidence/health constraints.
- AI_Project_Meeting_Notes.docx — blockers, decisions, actions, owners, dates and one deliberate unknown-owner/date review.
- AI_Project_Sprint_Update.txt — current task states, delivery outlook and the complete risk digest.
- AI_Project_Task_List.csv — 18 tasks with consistent owners, dates, dependencies and linked requirements/risks.
- AI_Project_Risk_Register.docx — 9 named risks with structured and natural-language assessments.

## Expected evidence

R-01 through R-09 provide explicit probability, impact, severity, status, owner and mitigation due date. Stated severity totals: 2 Critical, 3 High, 3 Moderate and 1 Low. All nine risks are Open. Medium means Moderate in this dataset. Probability is not an overall delivery forecast; risk severity is not calculated from probability and impact. Risk due dates are mitigation targets.

The digest repeats the same risk statements in the TXT and DOCX. The unchanged analysis deduplicates identical quotes, not all references to a real-world incident; other delivery/blocker statements can also be returned as risk entries. UI counts therefore describe returned records and need not equal nine unique risks. Missing ratings on those additional records must remain unknown. Retrieval remains bounded; use the optional existing review focus if further source material is needed.

## Demo flow

1. Create a new workspace to keep these sources separate from previous projects.
2. Upload all six files on Documents and wait for indexing.
3. Open Overview. Existing automatic analysis prepares scope, risk, blockers, health, documentation and the assistant briefing.
4. Review Risk Intelligence first, then the concise health, risk, action and scope summaries. Inspect nodes and evidence records; use filters and View Details.
5. Open detailed analysis/intelligence pages for full quotations, calculations and the assistant. Ask an unsupported question to see an honest insufficient-evidence answer.
6. Use Export / Download in Overview's Connected workflow for PDF or Word.

No health score or test-pass count is hard-coded in this sample. Actual returned values depend on the existing analysis and retrieved evidence. Existing application code does not preload these files; they enter the knowledge base only when you upload them.
